# VLM 的 RL 训练

> 记录于 2026-07-31

## Q: 什么情况下用 RL 训练 VLM？训练过程是什么样的？RL 在优化什么？

### 什么情况下用 RL

RL 在 VLM 训练中主要用于**对齐 (alignment)** 阶段，而非预训练阶段：

1. **RLHF（人类反馈强化学习）** — 当模型已有基本生成能力但需要对齐人类偏好时：
   - 输出不够 helpful（太简短、不完整）
   - 输出不够 harmless（偏见、不安全内容）
   - 输出不够 honest（幻觉、编造图像中不存在的物体）
   - 风格不符合预期（人类标注者觉得"A 比 B 好"但无 ground truth）

2. **需要优化不可微分的指标** — 很多真正关心的东西无法直接反向传播：
   - 人类偏好（"这段描述读起来更自然"）
   - 任务成功率（Agent 是否点对了按钮）
   - 事实正确性（VQA 最终答案对不对）

3. **多步推理 / Agent 场景** — VLM 做多步决策时（GUI 操作、机器人控制、工具调用），每一步影响后续状态，天然适合 RL 的序列决策框架。

4. **DPO/GRPO** — 有偏好数据但不想训练单独的 reward model 时的轻量替代方案。

### 训练过程（四阶段）

```
预训练 → SFT → Reward Model 训练 → RL 微调
(无RL)   (无RL)  (仅RLHF需要)     (PPO/GRPO)
```

**阶段 1：预训练** — 视觉编码器 + LLM 主干在大规模图文对上训练（如 CLIP 对比学习 + 生成式训练）。

**阶段 2：SFT（监督微调）** — 高质量 (图像, 指令, 理想回答) 三元组上做 next-token prediction。产出 RL 的起点策略 π_ref。

**阶段 3：训练 Reward Model** — 对每个 prompt 生成多个回答，人类排序，训练 r(x,y) 预测偏好分数。

**阶段 4：RL 微调（核心）** — 对每个 prompt：
1. 策略 π_θ 生成回答 y
2. Reward model 打分 r(x, y)
3. 计算 advantage，用 PPO 更新：最大化 A · log π_θ(y|x) - β · KL(π_θ || π_ref)

**现代变体：**
- **DPO**：跳过 reward model，直接在偏好对上优化
- **GRPO**：组内相对比较，无需 value network，更省显存

### RL 在优化什么

**数学上：**
$$\max_\theta \ \mathbb{E}[r(x, y)] - \beta \cdot D_{KL}(\pi_\theta \| \pi_{\text{ref}})$$

- 第一项：期望奖励最大化
- 第二项：KL 惩罚，防止偏离 SFT 模型太远，避免 reward hacking

**Reward Model 具体打分维度：**

| 维度 | 说明 |
|------|------|
| Helpfulness | 回答是否完整、有用、正确响应指令 |
| Harmlessness | 是否拒绝有害请求、不产生危险内容 |
| Honesty | 是否承认不确定性、不编造信息 |
| Visual accuracy | 描述是否与图像内容一致（不幻觉） |
| Format adherence | 是否遵循指定的输出格式 |

**模型内部的变化：**
- Token 级别调整概率分布 — 偏好通向高奖励完成的 token 序列
- 学会关注与问题相关的视觉区域
- 学会何时停止（不再无意义重复）
- 学会推理风格（chain-of-thought 的展开方式）

### 关键认知

RL 在 VLM 训练中不是主角，而是**最后的精修阶段**。它解决的核心问题是——"模型输出的概率高低"和"人类觉得好不好"是两件事，RL 负责对齐。
